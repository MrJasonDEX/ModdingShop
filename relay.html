Your port settings

Know exactly what to enter

You need two forwarding entries: one for the UDP range and one for the additional UDP port. You do not need to enter every port in the range separately.

Rule 1 · UDP range
3060–3080
3060-3080
Rule 2 · Additional UDP port
17376
17376
Important: use UDP for both entries, unless the tool's own documentation specifically tells you otherwise. The port range and the additional port are separate rules on routers that cannot represent both in one entry.

Step 01 · Windows

Find your PC's IPv4 address

First, find the local IP address of the Windows PC where you intend to run the Console Bridge. This is the address your router will forward traffic to.

  1. On your keyboard, press Windows + R.
  2. Type cmd and press Enter.
  3. In the Command Prompt window, type ipconfig and press Enter.
  4. Find the adapter you actually use: Wi-Fi or Ethernet.
  5. Look for IPv4 Address and write it down.
ipconfig
Example: 192.168.1.100 is an example address only. Use the IPv4 address shown on your own PC.

Before continuing: make sure you have the IPv4 address for the correct network adapter. Do not use the Default Gateway address as the PC address.

Step 02 · Router

Forward the UDP ports

Sign in to your router and look for a page called Port Forwarding, NAT, Virtual Server or similar.

  1. Open your router's administration page.
  2. Find the port forwarding section.
  3. Create a rule for UDP ports 3060–3080.
  4. Create a second rule for UDP port 17376.
  5. For both rules, enter the PC IPv4 address you found in Step 1.
  6. Save or apply the rules.
Rule 1 — UDP range
Name: MODDING XZ BO2 BRIDGE Protocol: UDP External/start port: 3060 External/end port: 3080 Internal/start port: 3060 Internal/end port: 3080 Destination IP: YOUR PC IPv4
Rule 2 — Additional port
Name: MODDING XZ BO2 BRIDGE 17376 Protocol: UDP External port: 17376 Internal port: 17376 Destination IP: YOUR PC IPv4
Do not forward these to the console. Both rules should point to the PC running the Console Bridge. If your router uses separate start and end fields, use 3060 and 3080 for the range rule. If it has one range field, enter 3060-3080.

If possible, reserve the PC's local IP in your router's DHCP settings so the address does not change later. Router settings differ, so use your router manufacturer's instructions if the labels do not match.

Step 03 · Windows security

Allow the ports through Windows Firewall

The router forwards traffic to your PC, but Windows Firewall may still block it. Add inbound UDP rules for both port entries.

  1. Open the Windows Start menu.
  2. Search for PowerShell.
  3. Right-click it and choose Run as administrator.
  4. Copy and run the first command below.
  5. Copy and run the second command below.
Allow UDP 3060–3080
New-NetFirewallRule -DisplayName "Modding XZ BO2 Bridge UDP 3060-3080" -Direction Inbound -Protocol UDP -LocalPort 3060-3080 -Action Allow
Allow UDP 17376
New-NetFirewallRule -DisplayName "Modding XZ BO2 Bridge UDP 17376" -Direction Inbound -Protocol UDP -LocalPort 17376 -Action Allow
What this does: creates inbound Windows Firewall rules for the specified UDP ports. Only run commands you understand, and only on the PC you administer.
Step 04 · Network analysis

Install Wireshark and Npcap

Wireshark lets you inspect network packets so you can see whether traffic is appearing while you use the bridge.

  1. Download Wireshark using the official link below.
  2. Run the installer.
  3. Install Npcap when the installer prompts you, if it is not already installed.
  4. Open Wireshark after installation.
  5. Select the adapter carrying your connection: Wi-Fi or Ethernet.
  6. Start capturing packets on that adapter.
Download Wireshark Official Wireshark website Download Npcap Packet capture driver for Windows
Tip: if you see several adapters, choose the one whose packet counter increases when you use your network.
Step 05 · Wireshark

Apply the BO2 port filter

Wireshark has a display-filter bar near the top. Use it to show packets associated with the bridge's configured ports.

  1. Make sure packet capture is running.
  2. Click the display-filter bar at the top.
  3. Paste the filter below.
  4. Press Enter to apply it.
Full bridge filter
(udp.port >= 3060 && udp.port <= 3080) || udp.port == 17376
Range only
udp.port >= 3060 && udp.port <= 3080
Additional port only
udp.port == 17376
Seeing no packets? Check the adapter, make sure capture is running, and generate traffic by starting the bridge and using BO2. An empty display does not, by itself, prove that the router is misconfigured.
Step 06 · Console Bridge

Download and run the bridge

  1. Get the Console Bridge files from the official ModdingXZ post or project link.
  2. Extract the downloaded archive if it is compressed.
  3. Read any included instructions before launching the tool.
  4. Run the bridge on the same PC whose IPv4 address you forwarded in Step 2.
  5. Keep the bridge running while testing BO2.
Only use files you trust. Scan downloads with your security software and verify the source. Do not disable Windows security protections just because an executable asks you to.

Step 07 · In-game test

Start BO2 and test a Custom Game

Once the network setup and bridge are ready, test the game in this order.

  1. Open Wireshark and start the capture using your filter.
  2. Launch the ModdingXZ Console Bridge.
  3. Start Black Ops 2 on the relevant PC/console setup.
  4. Open either Multiplayer or Zombies.
  5. Create the Custom Game or lobby as required by the tool's instructions.
  6. Ask your friend to try connecting.
  7. Watch Wireshark to see whether matching UDP packets appear during the test.
Both modes: this guide is intended for Black Ops 2 Zombies and Multiplayer. The exact in-game steps may differ depending on the tool and game configuration.
Step 08 · Network diagnostics

Check your public IP and understand port testing

Your public IP is the address your internet connection presents to external services. This is different from the local IPv4 address you found in Step 1.

Public IP lookup

Fetch your public IP using a third-party network utility API.

This request sends a connection to the external API, which can see your public IP. Do not share the result publicly unless you intend to.

UDP port-check limitation: an external TCP port checker cannot confirm that your UDP bridge ports work. UDP often has no simple open/closed response. The most useful test is to run the bridge and capture the actual traffic while a friend attempts to connect.
Read PortChecker API documentation

If your public IP appears to be shared with other customers or your router's WAN address differs from your public IP, ask your ISP whether you are behind CGNAT. Port forwarding may not work normally behind CGNAT without an appropriate public-IP solution.

Step 09 · Troubleshooting

Fix common BO2 errors

XGameRuntime failed — 0x80040154

This error can indicate a missing or unregistered Windows component, but the cause depends on the game files and system configuration. Check the ModdingXZ post for the specific fix supplied for this setup.

BO2 d3d11.dll error

If your error matches the issue covered by the ModdingXZ Telegram post, check the supplied DLL files and instructions. Back up the original file before making any change, and do not download replacement DLLs from untrusted sites.

Find the BO2 DLL post

Bridge is running but nobody can connect?

  1. Confirm both UDP forwarding entries point to your PC.
  2. Check both Windows Firewall rules.
  3. Verify the bridge is running and using the expected ports.
  4. Capture packets using the filter from Step 5.
  5. Check for CGNAT or double NAT if external connections still fail.
