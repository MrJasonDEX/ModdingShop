Before you begin

Know what you're setting up.

A relay setup depends on the tool you use, your PC network, your console connection and your router configuration. Check the instructions supplied with your particular tool rather than assuming every relay works the same way.

PC preparation

Check that your relay software, Windows network and any required drivers are installed and working.

Network configuration

Understand local IP addresses, router rules, firewall settings and whether your connection allows inbound traffic.

Testing & diagnostics

Use logs and packet captures to work out whether traffic reaches your PC and whether the relay responds.

Step zero

What you may need

Get these basics sorted before changing router settings or troubleshooting connection issues.

Windows PC

A supported Windows computer, the required relay application and any dependencies specified by its developer.

Console & game

Your compatible console, Black Ops 2 and the game/tool versions required by the particular relay method.

Router access

Access to the router's settings if port forwarding is required. Menu names differ between router brands.

Firewall access

Permission to check Windows Defender Firewall and allow only the software and network access you trust.

Diagnostic tools

Tools such as Wireshark can help inspect network packets when a connection is not behaving as expected.

Correct tool instructions

Read the release notes for your specific relay version. Ports and options can change between releases.

Important: Do not blindly open every port on your router. Use the ports documented for your exact tool, forward only what is required, and avoid exposing unrelated services to the internet.

Walkthrough

Relay setup guide

Work through these stages in order. The exact buttons and options depend on the relay software you're using.

01

Prepare your PC

Install the relay application from a source you trust. Read its release notes and check whether it requires administrator permissions, a particular runtime or a packet-capture driver. Avoid running unknown executables without checking them.

02

Check your local network

Open Command Prompt and run the following command to inspect your network configuration:

Windows Command Prompt 
ipconfig

Identify the active adapter and its IPv4 address. If you later create a router rule, make sure it points to the correct PC address rather than an old or inactive device.

03

Confirm the relay's port requirements

Check the documentation for your exact release. Community discussions have referenced UDP ports in the 3060–3080 range and port 17376. These are reference details, not a universal rule for every relay.

Use the protocol, port and destination specified by your tool. Do not assume that all listed ports need forwarding or that every port uses UDP.

04

Check your router settings

If the tool requires inbound connections, sign in to your own router and locate its port-forwarding or NAT rules. Assign the rule to the PC's current local IPv4 address and choose the documented protocol.

  • Keep the rule limited to the ports required by the tool.
  • Check whether your router supports the required protocol and port range.
  • Do not use your PC's public IP as the internal destination address.
  • Remove temporary rules when you no longer need them.
05

Review Windows Firewall

Check whether Windows Firewall is blocking the relay. If required, create a narrowly scoped rule for the trusted application or the exact documented port. Avoid turning the firewall off completely as a troubleshooting shortcut.

06

Start the relay application

Follow the software's own instructions to select the network adapter, configure any relay options and start the service. Read its console output or logs for errors. Do not assume the relay is running correctly just because the window opens.

07

Test the connection

Start with the least complicated test supported by your software. Check whether traffic reaches the PC, whether the application receives it and whether replies are sent. Test one change at a time so you can identify what fixed the issue.

08

Record what works

Keep a note of the relay version, game build, ports, adapter and any error messages. If you need community help, share the relevant error and configuration details, but remove passwords, public IP addresses and other private information first.

Network reference

Ports & connection checks

Keep the ports reported by your specific relay version handy while checking its documentation and logs.

Reported port references

Port / range Reference What to do
3060–3080 Reported relay range Confirm the exact ports and protocol in your relay's documentation.
17376 Additional community reference Check whether your particular tool needs it and which protocol it uses.
3074 / 3077 Previously discussed game / relay ports Do not assume these apply to your current software without checking.

Double NAT

If your router sits behind another router, forwarding traffic on only one device may not be enough. Check whether your internet provider's gateway is also routing traffic.

CGNAT restrictions

Some internet providers use carrier-grade NAT, which can prevent ordinary inbound port forwarding. Check with your provider if your router rules appear correct but inbound traffic never arrives.

Remember: A port-forwarding rule does not prove that a port is reachable. The application must be listening, the protocol must match, the firewall must allow the traffic and the wider network must permit the connection.
Advanced troubleshooting

Inspect traffic with Wireshark

A packet capture can help distinguish between traffic not arriving at the PC and traffic arriving but not being handled correctly by the application.

Basic workflow

Install Wireshark and, if required, its official capture driver. Select the active network adapter, start a capture, reproduce the issue and stop the capture once you have enough information.

Captures can contain sensitive information. Only inspect traffic you are authorised to capture, and review a file before sharing it publicly.

Get Wireshark
Display filter — UDP traffic 
udp
Display filter — port 17376 
udp.port == 17376
Display filter — ports 3060–3080 
udp.port >= 3060 && udp.port <= 3080

These examples are Wireshark display filters, not firewall commands. Change them to match the protocol and ports your software actually uses.

Fix the issue

Common problems

Search the troubleshooting notes below to narrow down the next thing to check.

Check the download source, release notes, Windows compatibility and any required runtimes. Look for an error message in the application or Windows Event Viewer. Only allow or run software you trust; don't disable antivirus simply to make an unknown program run.

First check whether the relay is running and listening on the expected interface. Use the appropriate packet filter to see whether traffic reaches the PC. If no traffic arrives, review the destination address, router rules, network path and possible CGNAT restrictions. If traffic does arrive, inspect the application logs and firewall rules.

Confirm the PC's current local IP, the exact ports, and the protocol specified by the tool. Make sure the application is actually listening. Check for another router, an ISP gateway or CGNAT between your router and the internet. A port checker may not accurately test UDP services.

Review the Windows Defender Firewall rules and logs. Add a narrow rule for the trusted application or documented port if necessary. Avoid disabling the firewall globally, especially on a public network.

Make sure you're capturing on the active adapter and using a suitable display filter. Start the capture before reproducing the issue. If the PC has Wi-Fi, Ethernet and virtual adapters, confirm which interface carries the traffic. Check capture permissions and driver installation too.

Compare the game build and tool release notes. Community-reported protocol and checksum values can become outdated, so confirm that your exact version is supported. Avoid mixing files or settings from unrelated releases.

Check whether there's a second router or ISP gateway upstream. Your provider may use CGNAT, which can prevent unsolicited inbound connections. Ask your ISP about your connection type and available options before making further router changes.

When asking the community, include your operating system, relay version, game build, the step that fails and the exact error text. Explain what you've already checked. Remove passwords, tokens and sensitive network details from screenshots and logs.
