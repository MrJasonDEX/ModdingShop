01 / Getting started

Welcome to the BO2 Relay Guide

This page brings together the networking concepts and community resources commonly discussed when setting up a Black Ops 2 relay environment. Use it as a reference rather than a guarantee that every setup will work the same way.

A relay setup can involve the game, a PC-side tool, your local network, router rules and the console. A problem at any one of these points can stop a connection from working.

Best approach: change one setting at a time, record the original value, and test again. This makes it easier to identify which change affected the connection.

What this guide covers

  • Community-reported BO2 update information.
  • Local IP addresses, router forwarding and firewall basics.
  • Wireshark filters for investigating UDP traffic.
  • Common NAT, double-NAT and CGNAT limitations.
  • Network diagnostics using publicly accessible APIs.
  • Common issues and links to the original community resources.

03 / Before setup

Requirements

Check the basics before changing router or game settings.

PC Windows + network access
Network Router or gateway access
Analysis Wireshark + Npcap if needed
Reference Correct tool version

Know your network first

  • Know whether the PC uses Wi-Fi or Ethernet.
  • Identify the router or gateway providing the connection.
  • Find the PC's local IPv4 address.
  • Check whether another router or ISP gateway sits upstream.
  • Use tools and files only from sources you trust.

Only change networks and devices you own or have permission to administer. Avoid disabling your firewall completely or opening unrelated ports to the internet.

04 / Router configuration

Port Forwarding

Port forwarding directs selected incoming traffic from your router to a particular device on your local network. It does not by itself guarantee that a game, relay tool or remote peer can connect.

Community-referenced ports

The following ports appeared in previous ModdingXZ community discussions. Treat them as reference values for the specific setup being discussed, not universal requirements for every BO2 installation.

Port / range Protocol Context
3060–3080 UDP Previously referenced relay-related range.
17376 UDP Additional port referenced in community guidance.
3074 UDP Port used as a traffic filter example.
3077 UDP Port used as a relay traffic filter example.

Confirm the ports and protocols required by the exact tool version you're using. Do not forward a range simply because it appears here if the application does not need it.

Find your local IPv4 address

On Windows, open Command Prompt and run:

ipconfig

Look for IPv4 Address under the adapter actually being used. It may look like 192.168.1.25 or 192.168.0.25. Your address may be different.

General router setup

  1. Sign in to your router's administration interface.
  2. Find the section named Port Forwarding, NAT or Virtual Server.
  3. Choose the correct local device address.
  4. Enter only the required port or range and protocol.
  5. Save the rule and check that the local device address has not changed.
  6. Test the application and inspect traffic if it still fails.

Router interfaces vary. Use your router manufacturer's official instructions if the menu names or fields differ. A forwarding rule does not create a listening service if the application is not actually listening on that port.

Windows Firewall

If the application is blocked, review the relevant Windows Defender Firewall rule. Prefer a narrowly scoped rule for the specific application or required port instead of turning the firewall off entirely.

05 / PC networking

PC Setup

Start with a stable network connection and confirm that the intended application is running. If the tool has its own network configuration, use the instructions supplied by that tool's developer rather than guessing at its settings.

Useful Windows commands

View IP configuration

ipconfig /all

View routing information

route print

View active network connections

netstat -ano

These commands display local network configuration and connections. They do not automatically prove that a remote UDP port is reachable. Avoid sharing output publicly without checking it for private addresses or other information you do not want to disclose.

06 / Traffic analysis

Wireshark

Wireshark captures and inspects network packets. It can help you determine whether traffic appears on the PC's network interface and whether replies are visible. It cannot decrypt arbitrary encrypted traffic or guarantee that a game connection is valid.

Download Wireshark from the official website. On Windows, its installer commonly offers Npcap, which is used to capture packets.

Useful display filters

Copy a filter into Wireshark's display filter bar.

udp
udp.port == 3074
udp.port == 3077
udp.port >= 3060 && udp.port <= 3080
udp.port == 17376

What to look for

  • Whether packets appear when you perform the action being tested.
  • Whether the traffic uses the expected network interface.
  • Whether replies are visible or only outbound traffic appears.
  • Whether the source and destination ports match your current setup.

Packet captures can contain IP addresses, account identifiers and other sensitive data. Do not publish full captures unless you have reviewed and sanitised them.

07 / Network limitations

NAT, Double NAT & CGNAT

What is NAT?

Network Address Translation allows devices on a private network to share a public-facing connection. Router forwarding rules can direct selected incoming traffic to a local device, provided the upstream network and firewall permit it.

Double NAT

Double NAT can happen when your own router sits behind another router or ISP gateway. A forwarding rule on only one device may not be enough if traffic also needs to pass through the upstream device.

CGNAT

Some internet providers place customers behind Carrier-Grade NAT. In that situation, the public IP address may be shared across multiple customers, and ordinary forwarding on your home router may not allow unsolicited incoming connections to reach your device.

Compare your router's WAN address with the public IP shown by the diagnostic tool below. A difference can indicate upstream NAT, although VPNs, proxies and other network arrangements can also explain it.

What can you do?

  • Check whether your ISP supplied a separate gateway and router.
  • Ask your ISP whether your connection uses CGNAT.
  • Ask whether a public IPv4 address or supported alternative is available.
  • Do not assume that a VPN or VPS automatically fixes every relay problem.
08 / Community information

PC-to-Console Bridge

Previous community discussions have covered PC-to-console relay arrangements and tool compatibility. The exact procedure depends on the application, console, game build and network environment.

A PC bridge, a relay utility and a router's port-forwarding rules are different parts of a network setup. One being configured correctly does not guarantee that the others are working.

When something does not connect

  • Confirm that the software and game versions are compatible.
  • Check that the PC and console are on the intended networks.
  • Confirm that the relevant application is running and has permission to use the network.
  • Use packet capture to observe traffic rather than assuming the cause.
  • Review the tool developer's documentation for its specific configuration.

10 / Common problems

Troubleshooting

Search the questions below to narrow down common network issues. These suggestions are starting points, not definitive diagnoses.

The relay or tool will not connect

Confirm the game and tool versions, check that the application is running, verify the network interface and review any firewall prompts. Use Wireshark to see whether relevant traffic appears. A failure to connect can have several causes.

Port forwarding does not seem to work

Check that the forwarding rule points to the correct local IPv4 address and uses the required protocol. Make sure the application is listening and consider whether another router or CGNAT sits upstream. A generic online port checker may not be able to test UDP correctly.

My public IP differs from the router's WAN IP

This can indicate double NAT, CGNAT, a VPN or another upstream network arrangement. Compare the addresses with your VPN status in mind and ask your ISP whether CGNAT is used.

Wireshark shows no packets

Confirm that you selected the interface actually carrying the traffic, start capture before repeating the action, and try a broader filter such as udp. Check that Npcap is installed if needed. No packets in the chosen capture does not prove that no traffic exists elsewhere.

I see outgoing packets but no replies

Possible causes include a remote endpoint that does not respond, incorrect destination details, filtering, NAT behaviour or a reply arriving through another interface. Capture traffic at the relevant point before deciding where the problem lies.

The public IP lookup failed

The API may be temporarily unavailable, your network may block the request, or your browser may be offline. Try again later or visit the provider's official site directly.

The DNS lookup returns no records

Check the spelling and chosen record type. A domain may have an A record but no AAAA record, for example. Some DNS answers can also be affected by DNSSEC validation, caching and resolver behaviour.

The website checker says the site is down

The target may block the checking service, time out, redirect unexpectedly or be temporarily unavailable. Try the site in your own browser. An external HTTP check is not a complete measurement of your local internet connection.

Everything looks correct, but BO2 still does not work

Networking is only one part of compatibility. Check the game build, tool version, console environment and current developer documentation. Community-reported values may be outdated and should be independently verified.

12 / Before you go

Final Notes

Network problems are easier to investigate when you separate local configuration, router behaviour, ISP limitations and application compatibility. Make one change at a time and use evidence from the relevant device or network interface.

The network diagnostics on this page are optional utilities, not an official BO2 status checker. Public IP, DNS and website status results cannot establish whether a relay is compatible with your game or whether UDP forwarding is working.
